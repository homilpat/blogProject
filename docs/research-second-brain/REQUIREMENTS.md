# Knowledge Hub 2.0 — 요구사항 명세

- 문서 상태: 제안 (승인 전)
- 우선순위: P0 = 필수, P1 = 후속
- 각 항목의 완료 판정은 구현 여부가 아니라 재현 가능한 테스트 결과로 한다.

## 1. 사용자 시나리오

**US-01 지식 등록**: 사용자는 책/논문 등 출처의 제목과 선택적 메타데이터를 기록하고 직접 작성한 학습 노트를 저장한다. 원문 PDF 없이도 사용 가능하며, 이때 원문과의 일치 여부는 시스템이 확인하지 못한다.

**US-02 자동 구조화**: 노트 등록 또는 수정 후 사용자의 추가 카테고리 입력 없이 주요 개념과 출처 기반 주장이 추출된다.

**US-03 자동 연결**: 서로 다른 노트의 개념/주장 사이 연결 후보가 발견되면 근거와 관계 유형이 기록된다. 의심스러운 병합은 확정하지 않는다.

**US-04 내부 질의응답**: 사용자는 여러 노트의 개념을 조합한 질문을 할 수 있고, 답변은 정확한 노트 근거를 제시한다.

**US-05 연구 가설**: 사용자는 "내 지식에서 연구 가설을 도출해줘"를 요청할 수 있으며 가설별 근거, 반론, 검증 절차, 부족한 지식을 받는다.

**US-06 공백 기반 학습**: 무엇을 더 공부해야 하는지 추상적인 추천이 아닌 특정 가설의 불확실한 전제와 연결된 내용으로 설명된다.

**US-07 학습 문제 (P1)**: 사용자가 요청하면 내부 노트 내용으로 문제를 생성하고 답안을 평가한다. 미응시 개념은 이해했다고 표시하지 않는다.

| --- | --- | --- | --- |
| FR-001 | P0 | 노트 생성/조회/수정/삭제 및 출처 정보 저장 | 원본 보존, 사용자별 권한 검사 |
| FR-002 | P0 | 노트 버전 및 파생 데이터 연결 | 노트 수정 시 옛 근거 무효화 여부 확인 |
| FR-003 | P0 | 구조화된 개념 및 주장 추출 | JSON Schema 유효성, 원문 구절 정렬 확인 |
| FR-004 | P0 | 동일 개념 후보 탐색 및 중복 방지 | 동의어/동형이의어 테스트 |
| FR-005 | P0 | 근거 있는 관계 및 그래프 증분 갱신 | 각 활성 관계의 원본 구절 존재 |
| FR-006 | P0 | 내부 벡터 + 그래프 검색 및 다중 청크 수집 | 복합 질문의 관련 문서 재현율 평가 |
| FR-007 | P0 | 질의에 따른 자율 내부 검색 재시도 | 반복 횟수 제한 및 실행 이력 기록 |
| FR-008 | P0 | 답변 주장 단위 근거 검증 | 근거 없는 단정 제거 또는 보류 |

| FR-010 | P0 | 가설의 반론, 전제, 불확실성 도출 | 입력 근거와 비판을 구분 저장 |
| FR-011 | P0 | 필요한 지식 공백 및 후속 학습 항목 도출 | 가설 전제와 gap 연결 추적 |
| FR-012 | P0 | 연구 실행 상태, 도구 호출, 실패 및 중단 기록 | 재시도 시 중복 데이터 미생성 |
| FR-013 | P0 | 개인별 노트, 벡터, 그래프, 실행 이력 접근 격리 | 다른 사용자 데이터 접근 테스트 실패 |
| FR-014 | P0 | 내부 근거 부족 시 정직한 응답 | 임의 외부 사실/가짜 인용 없음 |
| FR-015 | P0 | 노트 수정/삭제에 따른 인덱스 및 관계 갱신 | stale 연결과 인용이 남지 않음 |
| FR-016 | P1 | 그래프 시각화 및 사용자 관계 교정 | 수정/승인 이력 재확인 가능 |
| FR-017 | P1 | 노트 기반 퀴즈/평가 | 생성 문제의 노트 근거 확인 |
| FR-018 | P1 | 새로운 노트 기반 선택적 인사이트 후보 생성 | 근거가 부족하면 가설 없음 가능 |

## 3. 지식 종류와 상태

| 유형 | 설명 | 허용 상태 |
| --- | --- | --- |
| Source | 사용자 원본 노트, 책/논문 서지정보 | active, revised, deleted |
| Claim | 노트에서 추출한 주장, 노트 자체의 사실성 미검증 | extracted, evidence_aligned, disputed, stale |
| Concept | 용어 및 문맥별 개념 | candidate, active, merged |
| Relation | 개념/주장 간 방향성 연결과 근거 | candidate, supported, rejected, stale |
| Hypothesis | 에이전트가 생성한 검증 전 가설 | candidate, reviewed, rejected, tested |
| KnowledgeGap | 미충족 전제 또는 필요한 정보 | open, resolved, obsolete |

'사용자 승인'은 사실 검증과 다르다. **AI 추론을 사용자 원문으로 덮어쓰지 않는다.**

## 4. 관계 생성 품질 규칙

1. 관계 유형의 예: IS_A, PART_OF, USES, DEPENDS_ON, SUPPORTS, CONTRADICTS, RELATED_TO.
2. RELATED_TO를 남발하여 그래프를 조밀하게 만드는 행위는 품질 향상이 아니다.
3. 관계는 provenance(source_id, note_version, excerpt/offset), confidence, status, created_by를 갖는다.
4. LLM이 제안한 새 관계는 원본 문장이 실제로 뒷받침하는지 검사한다. 불명확하면 candidate로 보관한다.
5. 동일 이름의 다른 개념을 자동으로 병합하지 않는다.
6. 주장이 취소되거나 출처 노트가 삭제되면 연결 관계를 재평가한다.
7. 재색인은 같은 입력/버전에 대해 멱등적이어야 한다.

## 5. 연구 에이전트 실행 계약

**입력**: user_id, 연구 목표/질문, 검색 허용 범위(내부만), 최대 반복/예산, 관련 노트 선택 옵션.

**도구**: search_knowledge, explore_graph, inspect_source, compare_claims, generate_hypothesis, critique_hypothesis, identify_knowledge_gaps, save_research_result.

**상태**: run_id, goal, query_plan, visited_nodes, evidence_ids, candidate_hypotheses, critiques, unresolved_gaps, tool_history, remaining_budget, status.

**권한**: 검색과 가설 초안 생성은 자동, 기존 노트 원문 삭제/덮어쓰기 금지, 근거 없는 병합이나 사실 승격 금지.

**종료**: 검토 완료, 더 이상의 유의미한 신규 근거 없음, 예산/반복 횟수 초과, 사용자 취소, 도구 오류. 어떤 종료든 일부 결과와 실패 원인 기록.

## 6. 답변 정책

- 사실 주장은 반드시 내부 노트의 인용 가능한 발췌문 또는 그 발췌문들로부터의 명시적 추론에 연결한다.
- 연구 아이디어는 '가설 후보'로 표시하고 실험 전 성공/신규성을 단정하지 않는다.
- 출처 노트끼리 충돌하면 서로 다른 주장과 출처를 모두 제시한다.
- 실제 미등록과 검색 실패를 구별한다. 내부 탐색 후에도 찾지 못하면 '현재 등록된 지식에서 근거를 찾지 못했다'고 표현한다.
- 외부 검색 및 외부 지식 자동 보강은 제공하지 않는다.
- 한 노트만으로 답할 수 없는 경우 추가 노트와 관계를 탐색할 수 있으나 무한 반복하지 않는다.

## 7. 비기능 요구사항

- NFR-01 보안: Spring API, FastAPI, Qdrant, 그래프 조회에서 사용자 스코프 강제. 클라이언트가 제공한 user_id를 신뢰하지 않는다.
- NFR-02 무결성: MySQL 원본과 파생 색인의 버전 및 상태 정합성, 재처리 가능한 작업 큐.
- NFR-03 재현성: 모델명, 프롬프트/스키마 버전, 노트 버전, 실행 도구 이력을 기록.
- NFR-04 관측성: 검색 실패, LLM 구조화 추출 실패, 가설 폐기, 시간/비용을 기록.
- NFR-05 장애 정책: 임베딩 모델 오류 시 가짜 벡터로 대체하지 않는다. Qdrant 오류 시 성공처럼 보이는 인메모리 대체를 사용하지 않는다.
- NFR-06 확장성: 독립적인 지식 구축 작업 및 연구 실행 작업으로 구분하여 비동기 확장 가능하게 한다.
- NFR-07 테스트: 기존 블로그 CRUD 및 RAG 회귀 테스트와 개인 데이터 격리 테스트를 필수 포함.
- NFR-08 저작권/출처: 사용자 요약의 원본 접근 가능성을 주장하지 않으며, 상용 책의 본문을 무단 수집하거나 공유하지 않는다.
- NFR-09 정량 성능 목표: MVP 기준 측정 후 응답 시간, 비용, 정확도 합격선을 설정한다. 근거 없는 목표치 확정 금지.

## 8. 수용 예시

**사례 A / 복합 질의**: 선형대수 노트와 Transformer 노트를 등록한 뒤 "내가 공부한 행렬 연산이 Attention에 어떻게 사용돼?"라고 질문. 두 노트에서 근거를 찾고 연결 경로를 제시해야 함.

**사례 B / 지식 공백**: Transformer만 등록하고 FlashAttention과 비교를 요청. 근거 없는 FlashAttention 설명을 생성하지 않고 미확보 근거를 밝혀야 함.

**사례 C / 연구 가설**: Pose Estimation, VLM, Active Learning 요약 3개를 등록하고 선택적 VLM 검토 가설 도출을 요청. 가설, 세 자료의 연결 근거, 반론, 검증 계획과 필요한 추가 학습을 분리 출력해야 함.

**사례 D / 수정**: 이전 근거 노트의 관련 문장을 제거하면 해당 근거를 참조하는 관계와 가설은 stale 또는 재검토 상태가 되어야 함.

**사례 E / 격리**: 사용자 B는 사용자 A의 사설 노트에서 추출된 청크, 노드, 가설을 어떤 API 경로에서도 검색할 수 없어야 함.
